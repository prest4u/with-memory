# 故障排查与支持

先运行只读诊断：

```bash
eric-memory --data-dir /绝对路径/data status
eric-memory --data-dir /绝对路径/data doctor
eric-memory --data-dir /绝对路径/data doctor --json
```

## 数据库不存在

读命令不会创建数据库。先核对绝对 data directory；只有确定要创建新 library 时才运行 `init`，不要在猜测路径上初始化。

## `PERMISSION_REQUIRED`

检查 MCP 是否带 `--principal KEY`、principal 是否出现在 `harness list`，以及它是否拥有所需 capability/scope。不带 principal 会进入只读 legacy 身份。只从本地 CLI 授予缺少的那一项权限。

## 检索无结果

核对准确 project/workspace key、来源状态和事实状态。默认检索排除 deprecated 与 stale 文件；`%` / `_` 是普通字符，不是通配符。只有 `history:read` 身份能请求历史。

迁移后可运行 `verify --expect-query "已知实体"`。零结果不是绕过 ACL 或扫描全盘的理由。

## 来源扫描 truncated / stale

达到上限时 `source scan` 会明确返回 truncated 或 error，不会静默丢记录。收紧 include、排除生成目录，或在 100,000 文件支持目标内显式提高限制。缺失根和文件会立即标为 stale 并退出检索；符号链接始终跳过。

撤销再批准是新的同意事件，也会重置游标。

## 投影 dirty

SQLite 写入可能已成功提交。先看结果中的 `committed` 与 `projection`，修复 Vault 权限或可用性后运行 `sync`。不要因为投影失败就重复数据库写入。

## 备份或恢复失败

用 `backup verify` 校验准确绝对路径，保证磁盘空间足以容纳现库、安全快照和临时恢复副本。不要手工复制可能带活跃 WAL 的数据库。

## 迁移失败

原库应仍在原路径。保留错误和迁移前备份，只在副本上运行 `doctor`，不要反复对真实库执行 apply。scope 标签警告需要人工分类，但原标签不会被静默丢弃。

## MCP host 无法启动

先在终端用相同命令运行 `--version` 与 `status`。stdio 的 stdout 只能输出协议，诊断写到 stderr。官方服务器使用换行分隔 JSON-RPC，并由锁定的 MCP Python SDK 兼容现代与旧客户端。不要配置 HTTP URL。

## 脱敏支持包

```bash
eric-memory --data-dir /绝对路径/data support-bundle --output /绝对路径/with-support.json
```

分享前先自行打开 JSON 检查。默认不含事实或完整路径。禁止向公开 issue 上传 `memory.db`、WAL、原始来源/会话、发行私钥或完整 Vault。

安全报告按 [`SECURITY.zh-CN.md`](../SECURITY.zh-CN.md) 处理，并提供 With. 版本、OS/架构、schema、operation UID、脱敏错误码和合成数据复现步骤。
