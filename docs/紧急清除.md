# 紧急清除

`purge` 是破坏性的事故响应手段，不是普通记忆演进。日常变化应创建新事实并把旧事实标记为 deprecated。

## 执行前

1. 停止所有 MCP host 和正在使用 Vault 的进程。
2. 运行 `doctor`，再用 `history FACT_ID` 核对准确事实。
3. 检查正文是否存在于 Time Machine、系统快照、云盘、Obsidian Sync 或第三方副本；With. 无法清除这些副本。
4. 如果可恢复的更正已经足够，请使用 supersession。

## 命令

```bash
eric-memory --data-dir /绝对路径/data purge FACT_ID
```

命令会展示 fact UID、来源、投影和受影响的托管备份。只有本地用户输入准确 fact UID 后才会继续。MCP 永远不暴露 purge。

## With. 会清除

- fact 正文、实体/scope/检索/FTS/source 关系和取代边；
- 可能保留目标文字的 source locator 与 candidate 引用；
- With. 管理的 Obsidian 投影页，然后从干净数据库重新生成；
- 所有包含目标的 With. 自动备份；
- 整个可选工作上下文缓存及其来源启用记录；
- 通过 secure delete、checkpoint 与 VACUUM 处理 SQLite WAL 残留。

完成后会运行完整性检查并建立新的干净备份。唯一保留的是不含正文或内容哈希的 purge tombstone。

若投影预检查失败，数据库清除不会开始。若数据库清除后投影重建失败，With. 会删除全部自有投影页，避免陈旧正文残留。

预览会显示是否存在工作上下文缓存。临时库先于事实清除；临时库删除失败时，主库清除不会继续。之后需要重新启用选定来源。原始来源文件需要单独处理，其中仍可能保留目标文字。

## With. 无法清除

Time Machine、文件系统快照、SQLite 保证以外的取证残留、复制出的 export、截图、shell history、第三方同步和手工复制的 Vault 页面都不受 With. 控制，必须分别按对应服务的删除与保留流程处理。

当 `committed` 为 true、`purge_cleanup` 为 `pending` 时，事实已经删除。核对 `remaining_managed_backups`，将列出的准确路径传给 `backup remove PATH...`，输入 `REMOVE BACKUPS` 确认，再运行 `backup create`。若文件权限导致失败，先修复权限。不要再用已删除的 fact ID 重复执行 purge。
