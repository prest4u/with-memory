# 迁移、备份与恢复

## 连接安全

数据库打开方式明确分为只读、读写已有库和创建。`search`、`status`、`doctor`、`history`、`export`、`verify` 都使用只读 SQLite URI。只有 `init` 能创建缺失数据库。

## schema v1 → v2

应用迁移前先停止连接此库的旧版 CLI/MCP 服务；迁移完成后用新版重新连接。旧进程不会自动切换到替换后的数据库。迁移同时取得 With. 文件锁和 SQLite 写锁，并在锁内重新检查源快照；原始字段和值逐项核对。

`migrate --apply` 会取得跨平台独占锁，先做已验证备份，再把数据转换到独立的 v2 临时数据库；通过完整性、外键、行数、ID、实体、FTS、状态和取代链校验后，才原子替换原路径。任何转换失败都会保留原库。

旧整数 fact ID、时间、状态、实体、harness、文件记录、审计元数据和 Vault 路径全部保留。旧事实用 library UID 与整数 ID 生成确定性 UUIDv5；新对象使用 UUIDv4。

格式明确的 `project:` / `workspace:` 标签会转成结构化 scope。含糊或冲突标签保留原文并归入 user scope，由 `doctor` 报告。

## 备份

```bash
eric-memory --data-dir /绝对路径/data backup create
eric-memory --data-dir /绝对路径/data backup list
eric-memory --data-dir /绝对路径/data backup verify /绝对路径/backup.sqlite3
eric-memory --data-dir /绝对路径/data backup prune
```

每份备份都带元数据、SHA-256、SQLite 完整性结果、schema 版本、事实数与验证状态。每天第一次写机会会生成日备份，轮换保留 7 日、4 周、12 月。迁移、恢复、purge、更新前必须成功创建专用安全快照，否则操作停止。

WAL 可能活跃时只复制 `memory.db` 不是受支持的备份方式，请使用命令。

## 恢复

```bash
eric-memory --data-dir /绝对路径/data restore --from /绝对路径/backup.sqlite3
```

恢复会校验输入、锁库、快照当前状态、经临时路径恢复并原子激活，然后收紧权限并做完整性检查。本地终端必须输入 `RESTORE`；MCP 不暴露恢复。

可选的工作上下文缓存不进入备份。恢复前会移除整个临时库及来源启用记录，防止旧同意记录让失效文档重新可读。清理失败则停止恢复；完成后需要重新启用选定的临时来源。

## 无损回滚的条件

只有首次 v2 写入前才能无损回滚。已有 v2 写入时，With. 会先导出 v2 增量、展示潜在损失，并要求输入 `ROLLBACK`：

```bash
eric-memory --data-dir /绝对路径/data migrate --rollback \
  --incremental-export /绝对路径/data/exports/pre-v1-rollback-increment.jsonl
```

v1 无法表达 v2 candidate、principal、结构化 scope 或来源游标，因此导出文件必须与恢复后的备份一起保存。

## 恢复后检查

```bash
eric-memory --data-dir /绝对路径/data doctor
eric-memory --data-dir /绝对路径/data verify --expect-query "已知实体"
eric-memory --data-dir /绝对路径/data sync
```

投影失败不会回滚已提交数据库写入。结果会明确返回 `committed=true, projection=dirty`，再用 `sync` 修复可选投影。

数据库变更成功后，即使配置或操作日志写入失败，结果仍返回 `committed: true`。`configuration: pending` 和 `operation_log.status: failed` 分别指出后续失败。用 `doctor` 查看当前 schema，修复写入权限及配置；不要为了重试日志写入重复执行已提交的迁移或恢复。恢复前会检查全文索引及结构化检索词的一致性。

恢复来源须为已关闭的独立备份文件。有未合并 WAL 写入的来源会被拒绝；先通过 `backup create` 生成新备份。

恢复前须停止或断开使用目标库的所有 CLI/MCP 进程。Windows 无法替换仍被其他 SQLite 连接占用的数据库文件。
