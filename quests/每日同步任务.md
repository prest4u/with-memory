# 任务：可信记忆同步

先读 `skills/严格技能.md`。普通 harness 默认只能 search、扫描获准 source、提交 candidate；不能直接写 active、deprecate、review 或 purge。

## 1. 只读开场

```bash
eric-memory --data-dir "$DATA" status
eric-memory --data-dir "$DATA" search "$QUERY" --scope user
```

project/workspace 查询必须给准确 key。默认不请求 deprecated。

## 2. 增量收割

MCP 流程：

1. `memory_source_list` 只取分配给本 principal 的 approved source。
2. `memory_harvest_begin(source_uid)` 获取 run UID 和变化文件元数据。
3. 只读取返回路径；再次确认仍在 canonical root 内。不读 symlink，不读未变化正文。
4. 从中提炼 1–3 句、≤1,200 字符的 pointer；不得粘贴原文、凭据或未成年人个体表现。
5. 用稳定 `submission_uid`、`source_uid`、`source_locator` 调用 `memory_candidate_add`。
6. 全部成功后才 `memory_harvest_complete(run_uid,cursor)`。

CLI 由本地管理员执行时也优先用 `candidate add`，而不是 `add`。

无人值守的本地维护也可以使用 CLI 的两步入口：

```bash
eric-memory --data-dir "$DATA" harvest begin "$SOURCE_UID"
# 提炼并用 candidate add 提交全部适合保留的指针，再确认这一轮：
eric-memory --data-dir "$DATA" harvest complete "$RUN_UID" --cursor "$CURSOR"
eric-memory --data-dir "$DATA" sync --projection-only
```

未完成、失败或截断的收割会在下一次重新返回尚未确认的文件。为重试复用稳定 submission UID；任何未处理文件仍在队列时都不要 complete。`source scan` 和普通 `sync` 只是索引操作，会直接完成扫描；自动提炼流程不能用它们代替 harvest，也不要在提炼之前运行。

## 3. 冲突

candidate 里说明新现状和可能冲突的旧 fact ID，不要直接作废。由用户运行：

```bash
eric-memory --data-dir "$DATA" review
```

管理员在 accept 时选择 supersede；accept + supersede + audit + source link 会原子提交。

## 4. 投影与汇报

拥有 `sync:run` 的本地管理员可运行 `sync --projection-only` 修复投影。MCP 对应 `memory_sync(projection_only=true)`。这样不会推进尚未处理的来源。若结果是 `committed=true, projection=dirty`，数据库写入已经成功，不要重复提交。

向用户报告：查询、变化 source、candidate UID/状态、冲突、truncated/stale、待审总数和投影状态。禁止说 candidate 已成为事实，除非本地 review 明确接受。
