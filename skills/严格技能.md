# 严格技能：With.

产品叫 With. 命令仍是 `eric-memory`。本机记忆的唯一写入口是这个仓库的 CLI 或 MCP。Obsidian 只是投影。

## 必须

1. **只调用本仓库 CLI / MCP。** 禁止私自 `INSERT` / `UPDATE` / 直接改 `memory.db`。
2. **开工先 search。** 作用域用 `user` / `workspace` / `project`，与当前任务一致。默认结果里的 `deprecated` 不是现行。
3. **默认只提交 candidate。** 写入 1–3 句、最多 1,200 字符的指针；写清是什么、在哪、状态和下一扇门。只有本地交互式管理员审阅后才能变为 `active`。
4. **矛盾要在审阅时显式取代。** candidate 中说明新现状；由管理员在 `review` 中选择旧事实。不要改写旧行，也不要让普通 harness 直接 `deprecate`。
5. **已批准 source 才收割。** 只处理 `source list` 中归属本 principal 且仍为 `approved` 的根；用 `memory_harvest_begin` / `memory_harvest_complete`，禁止默认全盘扫。

## 禁止

- 凭据、密钥、cookie、token
- 未成年人到课记录或个体表现
- 整段会话、整篇文档原文
- 把文件正文写成事实（事实里只放路径）
- 把过期条当成现行建议
- 调用或模拟 `purge`（只允许本地交互式管理员做紧急清除）
- 为每个新 AI 工具重写一套内核

## 检索

```text
eric-memory search "$QUERY" --scope user
eric-memory search "$QUERY" --scope project --project 青云
eric-memory search "$QUERY" --include-deprecated
```

检索会融合实体、别名、CJK/Latin term、FTS5 与字面 LIKE；不要绕过 scope 或 status 过滤。普通 harness 看不到历史。

## 候选提交

```text
eric-memory candidate add --content "……" --entities "实体1,实体2" --scope user
```

MCP harness 必须使用获准来源，并为重试复用同一个 `submission_uid`：

```text
memory_candidate_add(content, submission_uid, source_uid, source_locator, scope, ...)
```

`add`、`deprecate`、`review`、`source approve` 与 `purge` 是本地管理员面，不是普通 harness 的默认写入口。

## MCP 对照

普通 principal 默认只会看到：`memory_status` `memory_search` `memory_candidate_add` `memory_candidate_list` `memory_source_list` `memory_harvest_begin` `memory_harvest_complete`。额外工具只有本地 CLI 显式授权后才会出现在 `tools/list`。

参数与 CLI 相同。不要发明第二套工具名。
